# 语义查询 (Query System)

> Query-Retriever 提供跨知识图谱的语义查询能力，支持双路召回 + RRF 融合。

---

## 一、设计目标

| 目标 | 说明 |
|------|------|
| 跨 KG 查询 | 一次查询同时搜索多个知识图谱（kg-proposition、kg-dialogue 等） |
| 语义理解 | 自然语言查询，不需要精确匹配关键词 |
| 可追溯 | 查询结果附带 `source_id`、`segment_id`、`original_text` |
| 可组合 | 支持标签过滤 + 向量搜索的组合查询 |

## 三、双路召回详解

### 向量召回

```
查询 "回流比过高的影响" → 向量化 → FAISS 搜索 → Top-20 命题
```

- 优势：语义理解，不依赖精确关键词匹配
- 局限：可能召回语义相关但非直接相关的命题

### 标签召回

```
查询 "回流比" → 标签索引 → 标签 "回流比" → 关联命题列表
```

- 优势：精确匹配，不会遗漏
- 局限：依赖标签质量，无法发现隐式关联

### RRF 融合

```
RRF(命题) = Σ 1/(k + rank_i)
```

两种召回结果通过 RRF（Reciprocal Rank Fusion）合并排序，互补长短。

## 四、三层回答策略

不是所有问题都走同一条路：

| 问题类型 | 查询路径 | 为什么 |
|---------|---------|--------|
| "X 是什么？"（事实/概念） | 向量→命题→original_text | 命题的 SRO 就是定义，原文足够 |
| "怎么论证的？"（论证链） | 向量→命题→segment_id→完整段落 | 需要段落上下文，不能只看单命题 |
| "作者怎么看？"（态度/语气） | 向量→命题→定位→RAG 全文检索 | 命题化丢失了态度信息，需要 RAG 补充 |

### 置信度不足时的降级策略

```
Query-Retriever 置信度不足
    │
    ▼
定位到相关章节（通过 tag + chapter）
    │
    ▼
加载完整章节原文（清洗版章节）
    │
    ▼
AI 生成答案 + 引用出处
    │
    ▼
合并 KG 结果（命题摘要） + RAG 结果（原文细节）
```

## 五、查询示例

### 示例 1：基础概念查询

```
查询："什么是锚定效应？"
→ 向量召回 → 命中 p_042 "锚定效应是人们在决策时过度依赖最先获得的信息的倾向"
→ 返回：命题 + original_text + 来源：《思考快与慢》ch03
```

### 示例 2：因果链查询

```
查询："回流比过高的影响是什么？"
→ 向量召回 → 命中 p_101 "回流比过高→能耗上升"
             → 命中 p_102 "能耗上升→成本增加"
             → 命中 p_103 "成本增加→经济性下降"
→ 返回：3 个命题，形成因果链
```

### 示例 3：跨 KG 查询

```
查询："Agent 在对话和论证中有什么不同观点？"
→ 双路召回 → kg-proposition 命中 p_201 "Agent 是自主决策系统"
            → kg-dialogue 命中 ex_045 "Q: Agent 的边界在哪？ A: 取决于自主程度"
→ 跨 KG 聚合 → 发现论证层和对话层对 Agent 的定义有差异
→ 建议触发 Evolution-Tracker
```

## 六、相关脚本

| 脚本 | 用途 |
|------|------|
| `scripts/embed_call.py` | 向量嵌入，将命题文本转为向量 |
| `scripts/rerank_call.py` | 重排序，对召回结果进行精排 |
| `scripts/query.py` | 查询入口，封装双路召回 + RRF 融合 |
| `scripts/run_evolution_tracker.py` | 演化追踪，检测命题间关系 |

## 七、未来优化方向

- **链式推理后处理**：查询时实时构建推理链（如"回流比↑ → 能耗↑ → 成本↑ → 经济性↓"），链不落盘、可追溯、可演化
- **多模态查询**：支持图片、表格作为查询输入
