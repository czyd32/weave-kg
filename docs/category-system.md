# 6 类内容切割 (Category System)

> 6 种内容类型的判定规则、切割方式、输出格式。

---

## 设计理念

**不分类文档，分类段落。** 一段素材可以同时产出命题、事件、Q&A——不人为压缩维度。

```
素材 ──→ §2 分类（段落级多标签）
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
  论证观点   事实事件   对话访谈
  (SRO命题) (事件节点) (Q&A对)
```

---

## ① 论证观点 → kg-proposition

**判定特征**：因果词（因此/所以/导致）、比较词（然而/但是/相比）、定义句、论点-论据结构

**切割单元**：原子命题（SRO 三元组）

**切割规则**：以因果/转折/主语变化为边界，每个命题为最小可独立理解的断言

**输出格式**：
```json
{
  "id": "p_001",
  "subject": "回流比",
  "relation": "过高导致",
  "object": "能耗急剧上升",
  "cause": "回流比增加意味着更多液体需要反复汽化冷凝",
  "effect": "再沸器和冷凝器的热负荷同步增加",
  "concepts": ["回流比", "能耗", "精馏"],
  "original_text": "回流比过高会导致能耗急剧上升，因为...",
  "chapter": "ch03",
  "page_range": "89-92"
}
```

**子类型**：
| 子类型 | 说明 | 示例 |
|--------|------|------|
| `claim` | 观点断言 | "直觉是不可靠的决策工具" |
| `definition` | 概念定义 | "回流比是指塔顶回流量与塔顶产品量之比" |
| `causality` | 因果关系 | "回流比过高导致能耗上升" |
| `comparison` | 比较判断 | "板式塔比填料塔更适合高液气比操作" |
| `method_step` | 方法步骤 | "精馏塔设计需先确定操作压力" |
| `design_principle` | 设计原则 | "塔板间距需保证雾沫夹带量在允许范围内" |
| `case_study` | 案例分析 | "某化工厂精馏塔改造案例..." |

## ② 教学教程 → kg-teaching

**判定特征**：定义词（是指/定义为）、操作词（首先/然后/步骤）、规则词（必须/应当/禁止）

**切割单元**：知识单元 + 前置依赖 DAG

**切割规则**：以定义/操作/规则词为边界

**输出格式**：
```json
{
  "id": "unit_001",
  "title": "配置 Python 环境",
  "content": "首先安装 Python 3.10+...",
  "prerequisites": [],
  "dependents": ["unit_002", "unit_003"],
  "type": "setup"
}
```

---

## ③ 对话访谈 → kg-dialogue

**判定特征**：问句、答句、立场转换（我认为/你觉得/不同意）、说话人切换

**切割单元**：Q&A 对 + 立场块

**切割规则**：以问句/答句/立场转换为边界

**输出格式**：
```json
{
  "id": "ex_001",
  "question": "你怎么看大模型的开源和闭源之争？",
  "answer": "我认为开源是趋势，但闭源在特定场景仍有优势...",
  "speaker": "张三",
  "stance": "支持开源为主",
  "stance_confidence": 0.85
}
```

---

## ④ 事实事件 → kg-events

**判定特征**：时间词、地点词、主体切换

**切割单元**：事件节点

**切割规则**：以时间/地点/主体切换为边界

**输出格式**：
```json
{
  "id": "evt_001",
  "timestamp": "2024-03-15",
  "location": "硅谷",
  "subject": "OpenAI",
  "action": "发布",
  "object": "GPT-5",
  "description": "OpenAI 在硅谷发布了 GPT-5 模型"
}
```

---

## ⑤ 参考手册 → kg-reference

**判定特征**：参数、配置项、API 名称、数值范围

**切割单元**：条目 + 参数分组

**切割规则**：以条目/参数分组为边界

**输出格式**：
```json
{
  "id": "ref_001",
  "name": "max_tokens",
  "type": "integer",
  "default": 4096,
  "range": [1, 128000],
  "description": "生成文本的最大 token 数",
  "category": "API 参数"
}
```

---

## ⑥ 叙事故事 → kg-narrative

**判定特征**：场景描述、冲突、视角转换

**切割单元**：情节节拍

**切割规则**：以场景/冲突/视角转换为边界

**输出格式**：
```json
{
  "id": "beat_001",
  "type": "setup",
  "description": "主角发现系统中的异常数据",
  "characters": ["张三"],
  "location": "数据中心",
  "tension_level": 3
}
```

## 多类型路由示例

```
素材："2024年，GPT-5发布。它的推理能力大幅提升，这意味着很多白领工作将被重塑。
       首先，我们需要理解什么是推理能力。推理能力是指模型从前提推导出结论的能力..."

§1 分割 → 3 个 Segment
§2 分类：
  Segment 1: "2024年，GPT-5发布。" → ④ 事实事件
  Segment 2: "推理能力大幅提升，这意味着白领工作将被重塑" → ① 论证观点
  Segment 3: "首先，我们需要理解什么是推理能力..." → ② 教学教程

§3 路由：
  Segment 1 → Event-Timeline
  Segment 2 → Proposition-Knowledge-Graph
  Segment 3 → Knowledge-Unit-Tree
```
