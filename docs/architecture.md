## 二、核心设计决策

### 决策 1：段落级分类，非文档级

**问题**：传统知识管理按"整篇文档"归类。一篇访谈可能同时包含论证观点、事实陈述、教学讲解——归类到"访谈"就丢失了论证和教学的维度。

**决策**：按段落粒度分类。一段素材可以同时路由到多个知识图谱。

```
素材 "为什么我们总被直觉骗"
  ├── §2 分类 → 段落 1-3：论证观点 → 路由到 kg-proposition
  ├── §2 分类 → 段落 4-5：事实事件 → 路由到 kg-events
  └── §2 分类 → 段落 6：教学教程 → 路由到 kg-teaching
```

### 决策 2：共享层统一管理

**问题**：多个知识图谱各自维护标签和向量索引，会导致标签不一致、向量搜索需要跨多个索引。

**决策**：标签、向量、索引由 Ingest §5 Aggregate 统一写入，所有知识图谱共用一套基础设施。

### 决策 3：演化优于快照

**问题**：传统知识库是静态快照。新知识进入后，旧知识可能过时、矛盾，但缺乏机制追踪。

**决策**：引入 Evolution-Tracker，通过共识簇、讨论层、少数派保护机制支撑知识演化。新命题入库时自动检测与已有命题的关系（同质化/对抗/互补）。

### 决策 4：人在环内

**问题**：AI 自动裁决知识冲突风险高，可能压制正确但非主流的观点。

**决策**：Evolution-Tracker 只标记冲突，不自动裁决。所有输出需人确认。低权重高孤立度命题标记为 `minority_signal`，不删除。

### 决策 5：可追溯是底线

**问题**：知识单元脱离原文后，无法验证其准确性。

**决策**：每个知识单元必须包含 `source_id`、`segment_id`、`original_text` 字段，可回溯到原文段落和来源。

## 四、与外部系统的关系

### 上游：内容提取器

Weave 不负责从原始格式（PDF/视频/网页）提取文本。这部分由外部工具完成：

- PDF 提取 → 输出 `全文.md`（推荐使用 MinerU，支持公式/表格/图表强兼容）
- 视频字幕 → 输出 `字幕.md`（B站 downloader + OCR）
- 网页采集 → 输出 `文章.md`（mediacrawler + defuddle）

### 下游：RAG 问答层

Weave 的命题化会丢失原文的措辞、语气、论证起承转合。对于态度/语气类问题，需要 RAG 层补充：

```
用户问 → Query-Retriever（向量+标签）→ 置信度不足 → RAG 降级
                                              → 加载完整章节原文
                                              → AI 生成答案 + 引用出处
```

### 侧翼：LLM Wiki

LLM Wiki 擅长隐式关系发现和交互式可视化，可作为 Weave 的探索辅助层，但命题存证仍以 Weave 为准。

## 五、设计原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | 段落粒度 | 不分类文档，分类段落 |
| 2 | 联邦式目录 | 每个知识图谱独立目录，共享层统一管理 |
| 3 | 多对多路由 | 一段素材可以路由到多个知识图谱 |
| 4 | 不可变追加 | 知识单元一旦写入，不可修改（通过 evolution 字段追溯变更） |
| 5 | 人在环内 | 冲突标记，不自动裁决 |
| 6 | 少数派保护 | 低权重高孤立度命题标记但不删除 |
