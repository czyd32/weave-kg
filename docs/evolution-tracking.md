# 演化追踪 (Evolution Tracking)

> 知识不是静态的。Evolution-Tracker 追踪知识图谱中的命题演化，通过共识簇、讨论层、少数派保护机制支撑知识演化。

---

## 一、核心概念

### 为什么需要演化追踪？

新知识不断进入知识图谱，会遇到三种情况：

| 情况 | 示例 | 处理方式 |
|------|------|---------|
| **同质化** | 命题 A 和命题 B 说了同一件事 | 合并为共识簇 |
| **对抗** | 命题 A 说"开源是未来"，命题 B 说"闭源更安全" | 标记为讨论层，不裁决 |
| **翻转** | 作者 A 先支持 X，后反对 X | 标记立场演变 |

### 核心原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | 只追加不删除 | 历史版本通过 `evolution.changes` 数组追溯 |
| 2 | 不做自动裁决 | 标记冲突，人环内裁决 |
| 3 | 少数派保护 | 低权重高孤立度命题标记为 `minority_signal`，不删除 |

## 三、共识簇 (Consensus Clusters)

### 定义

多个来源对同一主题达成的共识，以标签为聚合键。

### 结构

```json
{
  "cluster_id": "cc_001",
  "label": "认知偏误",
  "propositions": [
    {
      "id": "p_042",
      "source": "《思考快与慢》ch03",
      "claim": "锚定效应是系统性认知偏误",
      "weight": 0.9
    },
    {
      "id": "p_103",
      "source": "唯一讲述者 BV114421U7cM",
      "claim": "锚定效应在定价中普遍存在",
      "weight": 0.7
    }
  ],
  "consensus_strength": 0.85,
  "minority_signals": []
}
```

### 来源多样性

同一个共识簇可以包含来自不同来源的命题：

```
共识簇 "直觉决策的局限性"
├── 书籍：《思考快与慢》→ 理论定义
├── 视频：唯一讲述者 → 案例实证
└── 论文：Kahneman 2011 → 实验证据
```

## 四、讨论层 (Discussion Layer)

### 定义

当两个命题对同一标签存在矛盾时，不合并也不删除，而是标记为讨论层。

### 结构

```json
{
  "discussion_id": "disc_001",
  "label": "开源 vs 闭源",
  "positions": [
    {
      "proposition_id": "p_201",
      "stance": "开源是未来",
      "source": "某技术博客",
      "reasoning": "社区驱动创新更快"
    },
    {
      "proposition_id": "p_305",
      "stance": "闭源有不可替代的价值",
      "source": "某企业白皮书",
      "reasoning": "安全性和商业可持续性"
    }
  ],
  "status": "open",
  "created_at": "2026-08-01"
}
```

## 五、少数派保护 (Minority Protection)

### 问题

高权重、多来源的共识命题可能压制正确但非主流的少数派观点。

### 机制

| 信号 | 判定条件 | 处理 |
|------|---------|------|
| 低权重 | 标签权重 < 阈值 | 标记 `minority_signal`，保留不删除 |
| 高孤立度 | 与其他命题的向量相似度 < 阈值 | 标记 `minority_signal`，等待后续关联 |
| 翻转信号 | 同一来源的立场发生 180° 转变 | 标记 `stance_flip`，记录演变历史 |

### 示例

```
命题 X："某个被忽视的安全漏洞"
→ 仅 1 个来源，权重低
→ 标记为 minority_signal，保留
→ 3 个月后，新来源证实了该漏洞
→ 升级为共识簇，weight 更新
```

少数派观点可能被后来的证据证实。标记但不删除，确保知识图谱的演化可追溯。

## 六、触发方式

| 触发方式 | 场景 | 频率 |
|---------|------|------|
| 入库自动触发 | §5 Aggregate 末尾，对所有新命题运行 | 每次入库 |
| 手动审计触发 | 用户质疑某个共识簇，要求重新审查 | 按需 |
| 定期巡检 | 对全量命题运行演化检测 | 建议每周/每月 |

---

## 七、输出

Evolution-Tracker 的输出包括：

| 输出 | 格式 | 说明 |
|------|------|------|
| 共识簇更新 | `consensus_clusters/{cluster_id}.json` | 合并/新增共识簇 |
| 讨论层更新 | `discussion_layer/{disc_id}.json` | 新增矛盾标记 |
| 演化报告 | `evolution_report.md` | 人类可读的演化摘要 |
| 少数派清单 | `minority_report.md` | 低权重高孤立度命题清单 |
