# Proposition-KG — 命题知识图谱

## 描述

将任意长文本通过固定工作流转化为结构化知识网络。核心创新：**以因果/逻辑跳跃为边界的命题切割**——不是按句子/段落机械切割，而是识别文本中的因果链、转折点和主语变化，将文本分解为最小独立语义单元（原子命题）。

**核心原则**：局部最优 ≠ 全局最优。知识网络的价值在于聚合——公理不是"写"出来的，而是多个独立来源的命题自然汇聚后"长"出来的。

## 使用场景

- 用户提供一篇长文/视频字幕，要求"结构化存储"或"提取知识"
- 用户需要将碎片化经验/观点整理为知识网络
- 用户需要跨多篇内容发现共同公理或冲突观点
- 用户说"把这个存到知识库"或"分析这篇内容的论证结构"

## 依赖声明

- **KG-Ingest**（上游，调用方）：本 Skill 作为 Ingest 的内部子 Skill，由 Ingest 在 Route 阶段调遣
- **Evolution-Tracker**（下游）：消费共识簇，检测同质化/对抗/翻转
- **Query-Retriever**（下游）：查询本 Skill 产出的命题

## 自由度声明

**低自由度**：命题切割规则是确定的（SRO 三元组格式），仅切割边界的准确率允许 AI 灵活判断。

## 命题切割规则

### 切割边界

| 边界类型 | 检测信号 | 示例 |
|---------|---------|------|
| 因果跳跃 | "因此""所以""导致""这意味着" | "回流比过高 → 能耗上升" |
| 转折 | "然而""但是""不过" | "直觉快速，但不可靠" |
| 主语变化 | 讨论对象从 A 切换到 B | "板式塔…填料塔…" |
| 比较关系 | "相比""比…更" | "板式塔比填料塔更适合高液气比" |
| 定义句 | "是指""定义为" | "回流比是指塔顶回流量与塔顶产品量之比" |

### 命题格式（SRO 三元组）

```json
{
  "id": "p_001",
  "segment_id": "seg_001",
  "source_id": "article-2026-001",
  "subject": "回流比",
  "relation": "过高导致",
  "object": "能耗急剧上升",
  "cause": "回流比增加意味着更多液体需要反复汽化冷凝",
  "effect": "再沸器和冷凝器的热负荷同步增加",
  "concepts": ["回流比", "能耗", "精馏"],
  "original_text": "回流比过高会导致能耗急剧上升，因为...",
  "chapter": "ch03",
  "page_range": "89-92"
}
```

### 子类型

| 子类型 | 说明 | 示例 |
|--------|------|------|
| `claim` | 观点断言 | "直觉是不可靠的决策工具" |
| `definition` | 概念定义 | "回流比是指塔顶回流量与塔顶产品量之比" |
| `causality` | 因果关系 | "回流比过高导致能耗上升" |
| `comparison` | 比较判断 | "板式塔比填料塔更适合高液气比操作" |
| `method_step` | 方法步骤 | "精馏塔设计需先确定操作压力" |
| `design_principle` | 设计原则 | "塔板间距需保证雾沫夹带量在允许范围内" |
| `case_study` | 案例分析 | "某化工厂精馏塔改造案例..." |

## 工作流

```
1. 接收 Segment（来自 Ingest §3 Route）
2. 命题切割（识别因果/转折/主语变化边界）
3. SRO 提取（主语-关系-宾语 + 因果链）
4. 关键词提取（concepts 字段）
5. 标签建议（_tags.json）
6. 输出到 .ingest/{batch_id}/propositions/
```

## 质量检查

| # | 自检问句 |
|---|---------|
| 1 | 每个命题是否可独立理解（不依赖上下文）？ |
| 2 | 每个命题是否包含 original_text？ |
| 3 | SRO 三元组是否完整（subject/relation/object 非空）？ |
| 4 | 因果链是否保留（cause/effect 字段）？ |
| 5 | 标签是否与 concepts 一致？ |
