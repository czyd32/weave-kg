# Query-Retriever — 语义查询

## 描述

知识图谱的搜索引擎。不入库管道，按需查询。核心职责：**接收自然语言查询 → 分解为子查询 → 双路召回（向量+标签）→ RRF 融合排序 → 跨 KG 聚合 → 返回结构化结果**。

**一句话定位**：Ingest 负责"写"，Evolution-Tracker 负责"审"，Query-Retriever 负责"查"。

## 使用场景

- 自然语言提问："Agent 赛道有哪些主流观点？"
- 跨 KG 联合查询："论证和对话中关于 Agent 的不同观点？"
- 标签过滤查询："所有关于'开源模型'的命题，按时间排序"
- 矛盾发现："关于'Agent 可行性'，有没有相反的观点？"

## 依赖声明

- **KG-Ingest**（上游，数据源）：入库管道产出知识图谱数据
- **Evolution-Tracker**（下游，建议触发）：发现矛盾时引导用户触发
- **Insight-Weaver**（下游，调用方）：调用本 Skill 检索素材用于综述
- **共享层**：`_shared/` 向量空间、`tags/` 标签索引

## 自由度声明

**中自由度**：检索算法是确定性的（向量相似度、RRF 融合公式），查询分解和结果展示允许 AI 灵活判断。

## 查询流程

```
用户提问
    │
    ▼
§1 查询分析 → 提取意图、关键词、目标 KG
    │
    ▼
§2 双路召回
    ├── 向量召回：查询向量化 → FAISS 搜索 → Top-K
    └── 标签召回：关键词匹配标签 → 索引查询 → 关联命题
    │
    ▼
§3 RRF 融合 → 合并 + 去重 + 排序
    │
    ▼
§4 跨 KG 聚合 → 按 segment_id 拉回完整段落上下文
    │
    ▼
§5 结果展示 → 命题 + original_text + 段落上下文 + 关联标签
```

---

## 三层回答策略

| 问题类型 | 查询路径 | 为什么 |
|---------|---------|--------|
| "X 是什么？"（事实/概念） | 向量→命题→original_text | 命题的 SRO 就是定义 |
| "怎么论证的？"（论证链） | 向量→命题→segment_id→完整段落 | 需要段落上下文 |
| "作者怎么看？"（态度/语气） | 向量→命题→定位→RAG 全文检索 | 命题化丢失了态度信息 |

## 置信度不足时的降级策略

```
Query-Retriever 置信度不足
    → 定位到相关章节（tag + chapter）
    → 加载完整章节原文
    → AI 生成答案 + 引用出处
    → 合并 KG 结果（命题摘要） + RAG 结果（原文细节）
```
